# API

The JSON API the app is built on, usable from scripts on your tailnet.

| Endpoint | Description |
| --- | --- |
| `GET /api/agents` | Current agent list (every host's on a hub; each agent has `host` and `id` = `<host>/<pane_id>`) and `hosts` (`name`, `local`, `status` `ok`/`connecting`/`down`, `error`, `last_seen`, `agents`). |
| `GET /api/hosts` | Just the `hosts` status list. Each host has `version` (its binary version; for a peer, read from its `X-Comebye-Version` header, absent when unknown - e.g. a peer too old to send it) and, on a peer whose known version differs from the hub's, `version_mismatch: true`. |
| <a id="peers"></a>`GET /api/peers` | **Hub only, user role only.** `{"peers": [...], "version"}`: every peer, `source` `static` (from `-peers`) or `dynamic`, each with `name`, `urls`, `added_by`, `added_at`, `tag` (dynamic ones), and the host status fields (`status`, `error`, `class`, `agents`, `version`, `version_mismatch`). 409 `not_a_hub` on an instance that is not a hub (see `-hub-mode`); 403 `agent_forbidden` for the agent role. |
| `POST /api/peers` | **Hub only, user role only.** Body `{"name", "urls": ["https://..."], "tag"?}`. Adds a peer live: stored in `peers.json`, connected and health-checked at once. 201 with the peer as listed. `name` is a lowercase DNS label; `urls` are 1-4 `https` addresses on tailnet hosts (`*.ts.net`, the domains in `-peer-domains`, or a tailnet IP as a fallback). Errors: 400 `invalid_peer`; 409 `peer_exists` (a peer of that name exists - also when it is static, and then the message says it is set in `-peers`), `peer_is_local`, `not_a_hub`. |
| `DELETE /api/peers/{name}` | **Hub only, user role only.** Removes a dynamic peer: its stream and in-flight requests are cancelled and its agents leave the merged view. 204. 404 `unknown_peer`; 409 `static_peer` for one set in `-peers` (edit the hub's environment and restart). |
| <a id="announce"></a>`POST /api/peers/announce` | **Tagged nodes only**, through Serve with the capability (a user or anyone else gets 403 `announce_tagged_only`), and only with `-peer-self-register` (else 403 `self_register_off`). A node holding the capability registers itself. Body `{"name"?, "url"?}`; the default name is the node's short name and the default url `https://<node>`. The url must be on the caller's own node, as WhoIs identified it: 400 `invalid_peer` otherwise (or for anything the user-added rule refuses: `https`, `*.ts.net`). 201 with the peer as listed (`added_by` `tag:worker@<node>`, `tag`), or 200 when the same node was already registered under that name (no change). 409 `peer_exists`: the name belongs to another node, or this node has another name. 403 `cap_not_held` (through Serve, WhoIs does not show the capability), 401 (tailscaled does not know the address). |
| `GET/POST /api/hosts/{host}/agents/{target}/{output,transcript,prompt,keys,dialog,answer}` | Same as the routes below for a given host: the local host is served directly, a peer's agent is proxied to that peer (status and JSON errors pass through). |
| `GET /api/agents/{target}/output?lines=N` | Recent pane output; `&source=visible` reads the current screen instead (used for dialog snapshots). This, the transcript routes and their host-qualified forms answer the user, an agent on the target's host and a recorded coordinator; anyone else gets 403 `read_forbidden` ([the rule](security.md#reading-other-agents)). |
| `GET /api/agents/{target}/transcript?limit=N&skip=M` | Parsed session transcript (Pi or Claude Code; `format` says which), including any pending `ask` question. 404 `no_session` when there is none. |
| `POST /api/agents/{target}/prompt` | Body `{"text": "...", "wait": bool, "timeout_ms": int}`. 409 `agent_blocked` (herdr) or `dialog_open`: free text would be typed into the dialog (a permission prompt, a question, a menu, a `[y/N]` line), so answer it via `/answer` first, or hold the message with `POST /api/queue`. Delivery never types into an open dialog: the host that owns the pane reads the screen immediately before sending (cached status is not trusted; this covers a prompt forwarded from another host, the queue drainer and a launch's first prompt). Fail safe: an unreadable pane, or an agent that is blocked with nothing recognised on screen, also refuses. 409 `input_busy`: the agent's input box holds text (the user is typing, or stopped less than 5 s ago): nothing is typed over it. Read from the screen (Claude Code and pi; other kinds are not checked); the CLI then holds the prompt on the queue. Queued prompts, hub notices, briefs, mark asks and sweep notices wait for the box and retry every 2 s; a pending queue item then has `held` and `held_since`. |
| `POST /api/agents/{target}/keys` | Body `{"keys": ["esc"]}` (whitelisted). |
| `GET /api/agents/{target}/dialog` | `{"dialog": {...} \| null}`: the dialog the agent is waiting on (`kind`, `title`, `question`, `detail`, `options[]` with `label`/`description`/`checked`/`role`, `selected`, `multi`, `answerable`, `insert`, `cancel_label`, `fingerprint`). Only while the agent is `blocked` or has a pending transcript question, whatever its status (Claude's AskUserQuestion often leaves herdr on `done`). Option `role` is `other` (free text; never sent), `next` (the commit row: "Next", "Submit" on the last tab; committing with nothing ticked is valid) or `chat` ("Chat about this"; never an answer). `insert` means a text field is focused in vim INSERT mode and swallows the keys. |
| `POST /api/agents/{target}/answer` | Body `{"action": "select"\|"toggle"\|"submit"\|"cancel"\|"reset", "index": N, "fingerprint": "..."}`. `reset` sends one Esc and only while `insert` is set (leaves the text field; outside it an Esc would cancel the whole question, so it is refused). Re-detects the dialog; 409 `dialog_changed` (with the fresh `dialog`), `no_dialog` or `duplicate` (same dialog answered in the last 3 s), else sends the keys and returns `{"ok": true, "keys": [...]}`. |
| `GET /api/launch/options` | `{"enabled", "reason", "roots": [{path, label, git}], "kinds": [...], "default_kind", "model_kinds": [...], "recent": [{path, label, git}]}` for this host. `model_kinds` are the kinds that take a model (see `/api/models`). |
| `GET /api/models?kind=K` | The models this host offers for a kind: `{"host", "catalogs": [{kind, models: [{id, provider, name, thinking, note}], default, default_thinking, thinking_levels, source, exact, error}]}`. `id` is what `model` takes. `default` is the model the agent uses when none is passed (when known); `thinking_levels` (pi only) are the `thinking` values; `exact` says the list is complete (pi), else any name the agent accepts may be used; `source` says where it came from (`pi --list-models`, `curated`, a config file); `error` is set when listing failed (the list is then a fallback or empty). Cached for five minutes. Without `kind`: one catalog for each installed kind that takes a model. 400 `model_unsupported` for other kinds. Also `GET /api/hosts/{host}/models` (proxied to a peer by a hub). |
| `POST /api/agents/{target}/model`, `POST /api/hosts/{host}/agents/{target}/model` | Switches a running agent's model. Body `{"model", "thinking"}` (at least one; `thinking` for pi only). A running agent takes no flags, so the agent's host types its slash command into the prompt: claude `/model <name>`; pi `/model provider/id`, then `/thinking <level>`. Returns `{agent: {pane_id, name, agent}, model, thinking, commands}`; the commands were sent, the switch is not read back. The hub updates the worker's ledger entry. A pi model must be in pi's list on that host (an unknown `/model` would leave pi's selector open). Errors: `switch_unsupported` (kinds other than pi and claude), `model_required`, `bad_model`, `unknown_model`, `thinking_unsupported`, `bad_thinking` (400), `agent_busy` (409, the agent is not idle), `dialog_open` (409), `agent_not_found`, `unknown_host` (404). An agent cannot switch itself (`self`, 409). |
| `GET /api/launch/dirs?path=<abs>` | Subdirectories of a directory inside a launch root: `{path, label, parent, entries: [{name, path, git}], truncated}` (at most 300; hidden ones left out). Without `path`, the roots. 403 outside the roots, 404 missing. |
| `POST /api/launch` | Body `{"dir": "<abs>", "kind": "pi", "name": "...", "prompt": "...", "model": "...", "thinking": "..."}` (`kind` defaults to `default_kind`, `name` to the directory's; `model` and `thinking` are optional, empty meaning the agent's own default: no flag is passed. `thinking` is pi's `--thinking` level: off, minimal, low, medium, high, xhigh or max). Returns `{"agent": {id, host, pane_id, name, agent, ...}, "workspace_id"}`, plus `prompt_error` if the agent started but the prompt failed. Errors: `bad_kind`, `bad_name`, `model_unsupported`, `bad_model`, `unknown_model`, `thinking_unsupported`, `bad_thinking` (all 400, before a workspace is created), `agent_name_taken` (409), `outside_roots` (403), `launch_disabled` (403), or herdr's code with the workspace left open. With `"coordinator": true` (the Coordinator preset) `dir` is ignored: the agent starts in `-coordinator-dir`, named `coordinator[-N]`, with the harness's arguments and a first prompt pointing at the playbook, and the hub records its role (`launch/options` reports `coordinator_dir`). |
| `GET/POST /api/hosts/{host}/launch[/options,/dirs]` | The same for a given host (proxied to a peer by a hub). |
| `GET /api/repos` | The primary git checkouts in this host's launch roots (a root, its children and grandchildren): `{"repos": [{name, path, label, default_branch}], "truncated"}`. Also `/api/hosts/{host}/repos`. |
| `GET /api/checks?path=<abs>&branch=&base=` | A worktree's safety checks on this host: `{path, exists, primary, branch, dirty, dirty_files, unmerged_commits, base_used, repo, tip, in_progress, error}` (`unmerged_commits` -1 when unknown; `in_progress` names an unfinished rebase, merge, cherry-pick, revert or bisect). The path must be inside a launch root or the worktree root. `detail=1` adds `detail: {status[], commits[{sha, subject}], diff_stat, upstream, unpushed}`, `diff=1` also `diff`, `work_diff` and `diff_truncated`; `within=1` accepts any directory inside the checkout. Also `/api/hosts/{host}/checks`. |
| `GET /api/inspect?agent=<host>/<pane>&diff=1` | An agent's git state, checked on its host: `{agent_id, host, name, status, entry_id, branch, base, checks}` with `checks.detail` (the agent role may call it). |
| `POST /api/worker` | Starts a worker on this host: body `{"repo", "branch", "base", "kind", "model", "thinking", "name", "prompt"}` (`model`/`thinking` as for `/api/launch`; `{{worktree}}` and `{{base}}` in the prompt are filled in). Returns `{agent, workspace_id, worktree, branch, base, repo, reused}`. Errors: `bad_branch`, `bad_base`, `not_a_repo`, `branch_in_primary`, `path_exists`, `no_free_pane` (409), plus the launch errors. The hub calls a peer's; browsers use `/api/handoffs`. |
| `POST /api/remove` | Removes a session on this host: body `{"agent": "<pane>", "name", "workspace_id", "worktree", "branch", "base", "remove_worktree": bool, "allow_working": bool, "discard": bool, "discard_tip": "<sha>"}`. Returns `{closed: "workspace"\|"pane"\|"", worktree_removed, discarded, branch_deleted, kept, checks}`; 409 `agent_working`, `agent_changed`, `discard_changed`, `nothing_to_discard` or `primary_checkout` closes nothing. |
| `GET /api/ledger` | The hub's handoffs (`entries`, each with `live` status, `checks` a `candidate` hint, and for a handoff made by an agent `reply_to` and `callback` `{state: pending\|delivered\|expired, at, tries, to}`; only the latest 20 removed or failed) and standalone `marks`. 503 `ledger_disabled` without a state directory. |
| `POST /api/handoffs` | Body `{"host", "repo", "branch", "base", "kind", "model", "thinking", "name", "brief", "from"}`: runs the worker on that host and records it, with the `model` and `thinking` it asked for (`entry.model`, `entry.thinking`; also shown by `GET /api/ledger` and `GET /api/inspect`). Returns `{entry, worker}`; a failure returns the error with the recorded `failed` entry. An active handoff for the same host, repository and branch is returned instead (`"existing": true`; `"restarted": true` when its gone agent was replaced). 409 `handoff_in_progress` while the same one is starting. |
| `POST /api/handoffs/{id}/release`, `POST /api/handoffs/{id}/cancel` | Start a `waiting` handoff now (the answer is the handoff's, with `entry` and `worker`), or give up on it (`failed`, "cancelled by …"). 404 `not_waiting` unless the entry waits. |
| `POST /api/report` | A worker declares itself done: body `{"text"}` (cut to 20 kB). The caller is the agent role, matched to its running or finished handoff by host and pane (404 `no_handoff` otherwise; the user gets 400). The entry becomes `finished` with `report_source: "explicit"` and the requester's callback is queued; a later idle does not replace the report. |
| `POST /api/plans`, `GET /api/plans`, `GET /api/plans/{id}` | A plan groups handoffs into one change. POST `{title, size}` (size 1 to 20: how many workers the change takes; the title is reduced to one plain line of 80 characters); the creator is recorded when it is an agent. A handoff body may carry `"after": ["<member id or branch>", …]` (with `plan`; at most 8): it is recorded as a `waiting` entry and the answer has `"queued": true`. The hub starts it when every step it waits for has reported with `comebye report` (a step that merely went idle does not count), appending their reports, fenced and cut to 8 kB each (24 kB in all), after the brief in the worker's prompt; a step that failed or was removed unfinished fails it ("skipped"). 404 `unknown_step`, 409 `branch_in_use`, 400 `after_needs_plan`. A handoff body may carry `"plan": "<id>"` (404 `unknown_plan`, 409 `plan_full`; an existing worker joins). A plan is `{id, title, size, state: open\|done\|partial, done, members: [{id, host, repo_name, branch, status, outcome: pending\|ok\|failed, reported}], callback}`. It settles when `size` members exist and none is pending: `done` if all finished, `partial` if a handoff failed or a worker was removed unfinished. Settling pushes the user once (kind `plan`) and queues a notice to the creator; a member that works again reopens it. Also in `GET /api/ledger` as `plans`. |
| `POST /api/landings` | Body `{"agent_id", "note", "base"}`: record the user's OK to land a worker's work (`comebye land`). `note` (the user's words) is required; `base` defaults to `main`. The entry must be `finished` with a report, or `landing` and not yet reported (a retry); else 409 `not_ready`. The hub checks the worktree on its host first, to record the branch tip being approved. The entry becomes `landing` with `approval: {by, note, at, base, tip}`. Body `{"agent_id", "cancel": true}` undoes a landing whose prompt could not be sent (only before the worker starts working). When the landing report arrives, the hub checks the worktree, with the approved tip as a commit that must be in the base too: the entry becomes `landed`, or goes back to `finished`, with `land_check: {at, ok, base, verdict, landed}`, and the requester's callback is queued. Agents may call it, but not for themselves. |
| <a id="recall"></a>`GET /api/recall/status` | **User role only, like every `/api/recall` route**: the agent role and tagged nodes get 403, and nothing is forwarded to a hub ([why](security.md#searching-transcripts)). All are `Cache-Control: no-store`, and queries are not logged. Answers `{state, built_at, hosts, sessions, messages, snapshot}`; `snapshot` names the snapshot a pulled index came from, and `built_at` is always when the indexing machine built it; `state` is `ok`, `stale` (no build for over two hours), `outdated` (an older format, until the next `archive index`), `missing` or `unavailable` (could not be read). |
| `GET /api/recall/facets` | `{hosts, kinds, projects}`, each `[{value, n}]` with n sessions. |
| `GET /api/recall/search?q=&host=&kind=&project=&branch=&ledger=&role=&since=&until=&sort=&limit=&skip=` | One row per session: `{total, hits: [{host, kind, id, title, repo, branch, started, ended, messages, sub_messages, secrets, ledger_id, thread_id, verdict, matches, seq, sub, role, snippet}], commits}`. All words must match, stemmed; quotes give a phrase, and text that is not valid FTS5 is searched as plain words. `q` is required, up to 500 bytes. `role`: `said`, `commands` or `output`. `sort`: `rank` (default) or `new`. `limit` is capped at 50. `seq` and `sub` place the best match. `snippet` holds `\x02` and `\x03` around matched terms: split on them, and never treat it as markup. A `q` of 7 to 40 hex characters also returns `commits`, the sessions that made, pushed or saw that commit. |
| `GET /api/recall/recent?host=&kind=&project=&branch=&ledger=&since=&until=&limit=&skip=` | The newest sessions, for before anything is searched for: `{total, hits: [{host, kind, id, title, repo, branch, started, ended, messages, sub_messages, secrets, ledger_id, thread_id, verdict}]}`. The filters mean what they do in `search`. `limit` is capped at 50. |
| `GET /api/recall/sessions/{host}/{kind}/{id}?seq=&dir=&sub=&q=&limit=` | A page of one session: `{session, sub, subs: [{id, messages}], messages: [{seq, role, ts, text, tool_id, is_err, secret, full_len, hit}], before, after}`. `role` is `handoff` (seq -1, the brief), `user`, `assistant`, `tool` or `result`; a call and its result share `tool_id`. `full_len` is set when `text` is clipped. Without `seq`, the start; with it, `dir` is `around` (default), `before` or `after`. `sub` picks a subagent's thread. `q` marks matches in `text` as in a snippet. `limit` is capped at 200. 404 `no_session`: deleted, or not indexed yet. |
| `GET /api/recall/sessions/{host}/{kind}/{id}/hits?q=` | `{hits: [{seq, sub}], capped}`: where `q` matches in the session, in order, at most 500. |
| `POST /api/todos`, `GET /api/todos`, `GET /api/todos/{id}` | The to-do list: questions, decisions and follow-ups for the user, kept beside the briefing (hub only; a peer's agent role is forwarded). POST `{question, kind: decision\|action\|followup, context, links: [{label, url, handoff}], waiting, no_wait}`: the question is one line of 300 characters, the context markdown up to 8 kB, at most 10 links (`url` must be http(s)); `waiting` is the host-qualified id of the agent blocked on it, and defaults to the calling agent unless it is a coordinator or `no_wait` is set. Any agent may add; an identical open item is returned with `"duplicate": true`; 200 open items at most and 20 adds a minute per agent (429 `todo_full`, `todo_rate`). GET takes `?state=open\|answered\|done\|dropped\|all` (default: open and answered) and answers `{todos, open, answered}`. An item is `{id, question, context, kind, links, waiting: {id, name}, state: open\|answered\|done\|dropped, created_at, updated_at, created_by, answer: {text, by, via: app\|relay, at}, closed_by, drop_reason, notice: {state: pending\|sent\|expired}}`. Closed items are kept 14 days. |
| `POST /api/todos/{id}/answer`, `/done`, `/drop` | Body `{"text"}` (up to 4 kB) for an answer, `{"reason"}` optional for a drop. The user (the app) or a coordinator; any other agent gets 403 `coordinator_only`. A user's answer has `via: "app"` and queues a hub notice to a coordinator (fixed text, the item id only) that is retried until `done` or two hours; a coordinator's records the user's words it relayed (`via: "relay"`) and sends no notice. The hub never forwards an answer to the waiting agent: the coordinator does, then closes the item. 404 `not_found`, 409 `already_closed`. |
| `POST /api/marks`, `POST /api/marks/clear` | Body `{"agent_id": "<host>/<pane>", "reason", "by", "discard": bool, "no_ask": bool}`: mark a session ready to remove (`discard` proposes discarding its work), or unmark it. Marks in `GET /api/ledger` and `GET /api/removals` carry it; an `unsafe` answer is one of the review's `warnings`. |

### Tagged nodes through Serve

With `-ts-allow-cap`, a request with no `Tailscale-User-Login` whose
`Tailscale-App-Capabilities` header (Serve's `--accept-app-caps`) holds the
capability is treated the same way, on the normal Serve URL. WhoIs on
`X-Forwarded-For` must show a tagged node holding the capability, or the answer
is 403 `cap_not_held`; a missing, repeated or malformed `X-Forwarded-For`, or
an address tailscaled doesn't know, is 401. Anything but `/api/*` is 404. Every
other request is handled as if the setting were off.


POSTs must send `Content-Type: application/json` (see the security model).
Requests with `X-Comebye-Agent-Token` (the `comebye` CLI) get the agent
role and only the routes listed under [Coordinators](agents.md#coordinators); the
others answer 403 `agent_forbidden`.
`{target}` is a pane ID (for example `wS:p1`) or a live agent name; the
`/api/agents/{target}/…` routes always mean the local host. With
`"wait": true`, herdr starts a status wait in the same `agent.prompt` call,
so "send this and tell me when it's done" has no race.
